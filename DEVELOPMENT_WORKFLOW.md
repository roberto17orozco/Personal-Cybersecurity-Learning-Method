# **DEVELOPMENT WORKFLOW**
## *Official Documentation Standard — Development‑Driven Construction Order Workflow*

---

## **1. Overview**

Starting from **Project 6 – System Process & Network Activity Analyzer (PRO Version)**, all Bash and Python scripts in this repository follow a unified and professional development workflow based on the **Development‑Driven Construction Order** method.

### **Definition — Development‑Driven Construction Order**  
**Development‑Driven Construction Order** is a software development approach in which the script is constructed following the natural order in which its functional components should be built.  
Each block of code is created according to its logical role, dependencies, and importance within the system, ensuring that the script grows in a clear, structured, and maintainable way.

This method focuses on:

- identifying the core module of the system  
- defining evaluators and supporting logic  
- establishing configuration and utilities  
- adding secondary detection modules  
- building orchestration and execution layers  
- finalizing cosmetic and metadata components  

The result is a workflow that mirrors how an engineer naturally constructs a system from the inside out, improving clarity, maintainability, and architectural consistency.

---

This workflow was adopted after a personal technical realization, derived from:

- the foundational training acquired during the **Linux LFS101x** course, and  
- the practical experience gained while completing the **first five cybersecurity Bash projects** in this repository.

Through that learning journey, I identified that the **Development‑Driven Construction Order** is the most natural, scalable, and engineering‑oriented method for building system‑level scripts.  
This document formalizes that workflow.

---

## **2. Script Generation (Performed by Copilot)**

All scripts from Project 6 onward are fully generated by Copilot using a professional, user‑oriented structure.  
Each script includes:

- clean formatting  
- visually separated functional blocks  
- professional inline documentation  
- consistent engineering style  
- architecture aligned with real‑world system design  

The script is always produced **before** the README is written.

---

## **3. Script Breakdown Index (Provided by Copilot)**

For every project, Copilot provides a complete **Script Breakdown Index**, which includes:

- all major modules  
- all functions  
- all internal blocks  
- hierarchical titles and subtitles  
- numbering aligned with the visual structure of the script  

This index is designed to be copied directly into the README.

---

## **4. Development Blocks (Provided by Copilot)**

Each project includes a set of **Development Blocks**, also provided by Copilot.  
These blocks define:

- the logical order in which the script should be constructed  
- the role of each block within the system  
- the dependencies between modules  
- the exact block where each component is implemented  
- the title or subtitle where the block must be placed in the README  

**Important:**  
**Development Blocks** represent the **chronological order** in which the script is built.

Copilot does **not** provide the Script Breakdown Index with empty or pre‑filled sections.  
Instead:

> **Copilot provides ONLY the chronological order of the Development Blocks.**  
> **I manually place each Development Block into the correct title or subtitle inside the Script Breakdown section of the README.**

This ensures that the README reflects the true architectural structure of the system.

---

## **5. Visual Illustration (Performed by me)**

Once Copilot provides the ordered list of Development Blocks, I create a **visual illustration** of the script.  
This illustration includes:

- numbered blue boxes placed on the left margin of the code  
- one box per Development Block  
- alignment with the actual code structure  
- a visual map that shows the construction order of the script  

This illustration serves as a visual guide for understanding how the script was constructed using the Development‑Driven Construction Order method.

---

## **6. README Construction (Performed by me)**

I write the README using the materials provided by Copilot:

- the **Script Breakdown Index**  
- the **Development Blocks**  
- the **script itself** 

And the **visual illustration** designed by me.

The README must:

- integrate each Development Block into the correct block title  
- maintain the same structure as the script  
- reflect the real architecture of the system  
- remain consistent across all projects  

**All Development Blocks are manually typed by me into the appropriate Script Breakdown titles or subtitles.**

---

## **6. Consistency Across All Projects**

This workflow applies to:

- all remaining Bash projects  
- all future Python projects (after the IBM course)  
- any additional tools, utilities, or security scripts added later  

Every project follows the same pattern:

1. Copilot generates the script  
2. Copilot provides the Script Breakdown Index  
3. Copilot provides the ordered Development Blocks  
4. I create the visual illustration  
5. I write the README using all materials  
6. Adjustments are made only if needed to maintain clarity and consistency
